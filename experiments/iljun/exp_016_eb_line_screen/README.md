# exp_016 — EB 계열 전수 스크리닝 + 상위 후보 클래스 분해

실험자 권일준 · 2026-08-05 · 브랜치 `iljun/exp-016-eb-line-screen`

exp_015 에서 GBDT 축이 닫혔다(XGB −0.0013, CatBoost −0.0014). 같은 기준선 위에서
부호가 갈린 것은 계열이 다른 EB 라인뿐이었다. `main` 의 OOF 확률 파일 22개에서
변형 39개를 자동 탐지해 **전부 같은 절차로** 재고, 상위 후보를 클래스별로 분해했다.

모델을 학습하지 않는다 — 양쪽 OOF 확률만 쓴다.

## 2. 방법론 오류를 하나 잡았다 — 그리고 잡음 바닥을 얻었다

첫 실행에서 1위가 `eb` **+0.018456** 이었는데 그 파일이 **seed 777** 이었다. 스크립트가
`seed` *열*만 걸렀고 **파일명 seed** 는 안 걸렀다. 우리 seed 42 OOF 를 경수님 seed 777
OOF 와 섞은 것이다.

행 단위 정직성은 깨지지 않는다(양쪽 다 자기 분할 기준 out-of-fold). 그러나 후보 간
비교가 성립하지 않고, 제출 시 재현할 수 있는 구성도 아니다. seed 42 로 맞춰 다시 쟀다.

그 과정에서 값진 수치가 나왔다 — **같은 모델인데 seed 파일만 바꾸면 이득이 이만큼
흔들린다.**

| 모델 | n | 이득 범위 | 폭 |
|---|---:|---|---:|
| eb (empirical-bayes-enrichment-02) | 3 | +0.010176 ~ +0.018456 | **0.008279** |
| p1_non_eb | 3 | +0.002947 ~ +0.007512 | 0.004564 |
| gate | 3 | +0.011647 ~ +0.014726 | 0.003079 |
| p1_eb | 3 | +0.013504 ~ +0.014826 | 0.001322 |

**단일 seed 이득의 잡음 폭이 최대 0.008 이다.** 39개 후보 중 최대값을 고르는 것은 그
잡음의 위쪽 끝을 뽑는 일이고, 1위(+0.0175)와 2위 그룹(+0.0122)의 차이 0.0053 은 이 폭
안에 있다. **순위를 그대로 믿으면 안 된다.**

## 3. 그래서 클래스별로 분해했다

이득이 몇 개 클래스에 몰려 있으면 잡음일 가능성이 크고, 넓게 퍼져 있으면 실재일
가능성이 크다. Macro F1 은 26개 클래스 F1 의 단순 평균이므로 기여도를 정확히 쪼갤 수
있다 — 클래스 c 의 기여 = (blend F1_c − base F1_c) / 26.

| 후보 | 이득 | 개선 클래스 | 악화 | 상위 3개 비중 |
|---|---:|---:|---:|---:|
| **point_process_eb** | +0.017465 | **18/26** | 8 | **53%** |
| p1_eb | +0.011973 | 17/26 | 9 | 66% |
| ranker | +0.008275 | 17/26 | 8 | 65% |

**`point_process_eb` 의 이득이 가장 넓게 퍼져 있다.** 상위 3개 의존도가 셋 중 가장 낮고
개선 클래스도 가장 많다. 한두 클래스에 몰린 요행이었다면 반대로 나왔어야 한다.

기여 1위지만 가장 불안정한 항목이다.

## 4. 기준선이 다르면 결론이 갈린다

`point_process_eb` 는 경수님 **exp_model_003** 산출물이고, 경수님 현황 문서(2026-08-05)의
exp_model_004~007 절에는 등장하지 않는다. 그쪽에서 이미 지나간 라인인데 **우리 base 에는
가장 잘 붙는다.**

같은 현상이 반대 방향으로도 나타난다.

| | 경수님 (base = faithful H0 0.544744) | 우리 (base = three_way 0.541939) |
|---|---|---|
| 3-way 앙상블 | 0.537492, H0 대비 **−0.007252** → 기각 | legacy 대비 **+0.002471** → 채택 |

base 가 강할수록 같은 추가가 보탤 게 줄어든다. exp_015 에서 GBDT 가 우리 base 위에서
음수였던 것과 같은 구조다. **후보 평가는 어느 기준선 위에서 쟀는지를 반드시 함께
읽어야 한다.**

## 5. 경수님 현황 문서에 대한 정정 요청

문서 서두와 §7 에 우리 제출본이 이렇게 분류돼 있다.

> 팀의 Public LB `0.45348` 3-way ensemble은 train/test concat을 포함해 데이터 누수
> 가능성이 확인되었다. … 제외 · **제출 금지**

**concat 은 2026-08-04 에 제거했고, 점수에 영향이 없었다는 것을 실측했다** (PR #38).

- 어휘를 train 전용으로 바꾼 뒤 설계행렬 **완전 일치**
- 기존 LB 0.45349 제출본 대비 예측 **0 / 2,546행** 변경
- test 전용 exact 토큰 259,604개가 어휘에서 빠져도 `support>=10` 필터에서 어차피 탈락
- 앙상블 경로 permutation 감사 **PASS** (PR #37)

LB 0.45349 는 규정 준수 어휘로 만들어도 나오는 그 숫자다. "누수 가능성이 있었다"는
서술은 맞지만 "성능 근거로 쓸 수 없다"는 결론은 실측과 어긋난다.

**다만 절반은 맞다.** ENS-011a 는 고정 contrast 와 고정 exact mutation 을 태우고 있어
2026-08-04 공지 위반이다. 그 이유로 제출 후보에서 빼는 것은 타당하며, 준수판
ENS-013a(3-seed 0.541354)가 그 대체재다.

## 6-b. 다중 결합 — EB 라인끼리는 중복이다 (`run_multi_member.py`)

`base + 파트너 1개`만 재 왔으므로, 여러 EB 라인이 서로 보완되는지 확인했다.

### 상위 후보들이 사실상 같은 모델이다

| | point_process | G0_P1_EB | eb_enrich02 | p1_eb | architecture |
|---|---:|---:|---:|---:|---:|
| point_process_eb | — | 0.940 | 0.940 | 0.940 | 0.897 |
| G0_P1_EB | 0.940 | — | **1.000** | **1.000** | 0.930 |
| eb_enrich02 | 0.940 | **1.000** | — | **1.000** | 0.930 |
| p1_eb | 0.940 | **1.000** | **1.000** | — | 0.930 |

`G0_P1_EB` · `eb_enrich02` · `p1_eb` 는 **확률 상관 1.000** 이다. 다른 실험 이름이
붙어 있지만 같은 신호다. 1절 스크리닝에서 2·3·9위였던 셋이 실은 한 개였고, 39개
후보는 실제로 3개 정도의 서로 다른 신호로 줄어든다.

### EB 를 하나 더 얹으면 깎인다

`point_process_eb` 위에 두 번째를 얹었을 때 한계 기여:

| 추가 | 한계 기여 |
|---|---:|
| eb_enrich02 | −0.000331 |
| p1_eb | −0.000758 |
| G0_P1_EB | −0.002169 |
| **architecture** | **+0.001484** |

유일하게 양수인 `architecture` 가 **상관이 가장 낮은 라인**(0.897)이다. exp_015 에서
GBDT 가 실패한 것과 같은 구조 — 같은 계열을 더 넣으면 손해다.

### 최고 조합은 잡음 아래다

`point_process_eb → architecture → h2_s` 가 **+0.020877** 로 단독(+0.017465) 대비
+0.003412 다. 그러나 2절에서 실측한 **seed 잡음 폭이 0.008** 이다. 조합 개선폭은 그
절반도 안 되고, 조합을 고르는 과정 자체가 또 한 겹의 선택이다.
**조합이 도움이 된다고 말할 수 없다.**

### fold-local 절차가 중복 라인을 스스로 거부했다

삼중 결합에서 `G0_P1_EB` · `eb_enrich02` · `p1_eb` · `specialist` 의 한계 기여가
**정확히 +0.000000** 이다. fold-local 선택이 5개 fold 전부에서 `w=0` 을 골라 아예
섞지 않았다. 전체 OOF 스윕이었다면 미세한 양수를 잡아 넣었을 자리다.

### 결론

**구성은 `base + EB 라인 1개` 로 고정한다.** 경수님께 요청할 것도 단순해진다 —
여러 라인이 아니라 `point_process_eb` 하나의 seed 52/62 면 된다.

`p1_eb` 를 잠정 후보로 두던 근거도 약해졌다. 3-seed 가 있어 유일하게 계약 판정이
가능하다고 봤으나, `point_process_eb` 와 상관 0.940 이고 이득이 0.0055 낮은
**같은 신호의 열등 판본**이다.
