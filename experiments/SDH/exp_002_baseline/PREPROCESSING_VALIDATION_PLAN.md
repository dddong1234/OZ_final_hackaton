# 전처리 검증 및 제출 전략

## 1. 목적

현재 OOF 실험은 제한된 일일 제출 횟수를 활용하기 위해 모델, 전처리 및
soft voting 후보를 한 번에 탐색한 결과다.

OOF 점수가 높은 후보는 LB에 제출할 가치가 있지만, LB 결과만으로 전처리를
확정하지 않는다. 전처리의 효과를 먼저 동일한 모델 조건에서 분리해 검증한 뒤,
확정된 전처리 위에서 모델 튜닝과 앙상블을 진행한다.

실험 순서는 다음과 같이 통일한다.

```text
전처리 단독 비교
→ 반복 seed 검증
→ 전처리 확정
→ 모델 하이퍼파라미터 튜닝
→ 다른 모델 검증
→ OOF 기반 앙상블
→ LB 제출
```

## 3. 현재 결과의 해석

### 3.1 Logistic Regression 규제

`C=1.0`에서 `C=0.1`로 변경했을 때 OOF Macro F1이 다음과 같이 상승했다.

```text
0.34453 → 0.38300
차이: +0.03847
```

현재 데이터는 6,201행에 유전체 피처가 4,384개인 고차원 희소 데이터다.
규제를 강화한 Logistic Regression이 기본값보다 적합할 가능성이 높다.

다만 이는 전처리 효과가 아니라 모델 하이퍼파라미터 효과이므로 전처리 비교 시
`C`를 고정해야 한다.

### 3.2 Mutation burden

동일한 `C=0.1` 조건에서 `log1p(변이 유전자 수)`를 추가했을 때:

```text
0.38300 → 0.39657
차이: +0.01357
```

현재 가장 유망한 전처리 피처다. 다만 현재 구현은 변이가 존재하는 유전자 개수만
사용한다. 한 셀에 여러 변이가 기록된 경우까지 세는 실제 변이 토큰 수는 아직
포함하지 않았다.

### 3.3 Soft voting

Soft voting은 최고 단일 모델보다 OOF Macro F1이 약 0.003 높았다.

하지만 상위 조합이 모두 Logistic Regression 전처리 변형으로 구성되어 있고,
baseline·상수열 제거·최소 빈도 필터 후보의 예측이 매우 유사하다.

따라서 현재 soft voting 결과는 모델 다양성에 따른 안정적인 개선으로 단정하지
않는다. 반복 seed에서도 개선되는지 확인한 뒤 제출 후보로 확정한다.

## 4. 현재 전처리 후보 판단

| 전처리 | 현재 판단 | 근거 |
| --- | --- | --- |
| `fillna("WT")` | 필수 | test 결측치를 변이로 잘못 인코딩하는 문제 방지 |
| WT/변이 이진화 | 유지 | 모든 비교의 기본 인코딩 |
| 상수열 제거 | 선택적 유지 | 점수 차이는 거의 없지만 불필요한 열 제거 |
| `log1p(변이 유전자 수)` | 유망 | 동일 모델에서 OOF +0.01357 |
| 최소 변이 빈도 필터 | 추가 확인 | 개선 폭이 매우 작음 |
| Chi² 1,000/2,000 선택 | 우선 제외 | baseline보다 성능 하락 |
| TF-IDF 가중 | 우선 제외 | baseline보다 성능 하락 |

`Chi²` 결과는 현재 조건에서만 우선 제외한다. Mutation burden을 통제한 뒤의
피처 선택이나 다른 선택 기준은 별도 실험으로 다룰 수 있다.

## 5. 전처리 검증 기준

전처리를 비교하는 동안 모델과 CV 조건을 고정한다.

```python
LogisticRegression(
    C=0.1,
    solver="lbfgs",
    max_iter=2000,
    class_weight="balanced",
    random_state=42,
)
```

```python
StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42,
)
```

전처리의 `fit`은 반드시 각 fold의 train 부분에서만 실행한다. Validation과
test에는 `transform`만 적용한다.

## 6. 다음 전처리 실험

아래 후보를 동일한 모델·동일한 fold에서 비교한다.

| ID | 전처리 |
| --- | --- |
| A | WT 이진화 |
| B | A + 상수열 제거 |
| C | B + `log1p(변이 유전자 수)` |
| D | B + `log1p(실제 변이 토큰 수)` |
| E | B + 두 mutation burden 피처 모두 |
| F | E + 변이 유형별 개수 |
| G | E + 최소 변이 빈도 3/5/10 |
| H | E + 주요 hotspot 피처 |

### 6.1 Mutation burden 정의

두 burden 피처를 구분해서 검증한다.

1. 변이 유전자 수

```text
한 행에서 값이 WT가 아닌 유전자 컬럼 수
```

2. 실제 변이 토큰 수

```text
각 셀의 공백 구분 변이 토큰을 모두 합산한 수
```

예를 들어 한 유전자 셀에 `"F157L S1042F"`가 있으면:

- 변이 유전자 수에는 1 추가
- 실제 변이 토큰 수에는 2 추가

두 값은 모두 오른쪽 꼬리가 긴 분포이므로 `log1p`를 적용한다.

## 7. 전처리 확정 기준

1차 비교는 seed 42의 5-Fold OOF로 진행한다.

유망 후보는 다음 seed에서 반복 검증한다.

```text
42, 52, 62
```

전처리 채택 기준:

- 3개 seed 평균 OOF Macro F1이 baseline보다 높다.
- 특정 seed 하나에서만 개선되지 않는다.
- 클래스별 F1이 일부 클래스의 우연한 급등에만 의존하지 않는다.
- fold train에서만 전처리를 fit해도 개선이 유지된다.
- test를 사용해 전처리 기준이나 파라미터를 결정하지 않는다.

점수 차이가 작으면 다음 정보를 함께 확인한다.

- 3-seed 평균과 표준편차
- seed별 OOF Macro F1
- 클래스별 F1 변화
- 후보 간 OOF 예측 불일치율

## 8. 전처리 확정 후 모델 검증

전처리를 확정한 뒤 Logistic Regression의 `C`를 세밀하게 탐색한다.

```python
C_VALUES = [0.03, 0.05, 0.07, 0.1, 0.15, 0.2, 0.3]
```

그다음 동일한 전처리로 다른 모델을 검증한다.

- Logistic Regression
- SGD Logistic
- LightGBM
- CatBoost
- 필요 시 calibrated Linear SVM

단독 OOF 점수뿐 아니라 Logistic Regression과의 OOF 예측 차이를 확인한다.
단독 점수가 낮더라도 서로 다른 표본을 맞히는 모델은 앙상블 후보가 될 수 있다.

## 9. 앙상블 기준

앙상블 가중치는 OOF 확률로만 결정한다.

```text
OOF 확률 정렬
→ 제한된 가중치 탐색
→ OOF Macro F1 비교
→ 반복 seed 확인
→ 동일한 fold 모델의 test 확률 평균
```

가중치를 지나치게 세밀하게 탐색하면 OOF에 과적합될 수 있으므로 기본 탐색
간격은 0.1로 제한한다.

동일 계열 LR 후보만 섞어 발생한 작은 개선보다, 서로 다른 모델 또는 피처 표현을
사용해 반복 seed에서 유지되는 개선을 우선한다.

## 10. LB 제출 원칙

현재 `lr_burden_c0.1`은 기존 baseline보다 OOF가 크게 개선되어 LB에 진단용으로
제출할 가치가 있다.

다만 제출 결과는 전처리 확정 근거가 아니라 다음 가설을 확인하는 보조 정보로만
사용한다.

```text
log1p mutation burden과 강화된 규제가
기존 전체 train 단일 LR보다 test 일반화에 도움이 되는가?
```

제출 우선순위:

1. 반복 CV에서 검증된 최고 단일 전처리 모델
2. 해당 모델의 5-Fold test probability 앙상블
3. 반복 CV에서 개선된 soft voting
4. 서로 다른 burden 또는 변이 유형 피처를 사용한 후보

Public LB 점수만 보고 전처리나 가중치를 반복해서 변경하지 않는다.

## 11. 현재 결론

- 현재 가장 큰 개선은 LR의 `C=0.1`과 mutation burden에서 발생했다.
- 전처리 확정 전에는 모델과 CV 조건을 고정해야 한다.
- Mutation burden은 유전자 수와 실제 변이 토큰 수를 분리해 검증해야 한다.
- 유망 전처리는 seed 42/52/62에서 반복 검증한다.
- 전처리 확정 후에만 세부 모델 튜닝과 soft voting을 진행한다.
- 현재 LB 제출은 유망 후보에 대한 진단이며, 전처리 확정 절차를 대체하지 않는다.
